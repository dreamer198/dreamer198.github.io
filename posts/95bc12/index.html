PX4 + Gazebo + MAVROS + Onboard 多机仿真与实测启动指南

发表于2025-11-14|更新于2026-09-28|飞控与仿真
|总字数:865|阅读时长:3分钟

本文整理 PX4 + Gazebo + MAVROS + Onboard 控制程序的四种启动场景：单机仿真、多机仿真、单机实测和多机实测。多机时最容易出错的是实例编号、系统 ID 和端口的对应关系，文中单独列了一张对照表。

环境说明

项目 说明
PX4 SITL，使用 px4_sitl_default 构建
Gazebo PX4 官方支持的 Gazebo，命令中使用 gz_x500 模型
ROS ROS 2，配合 MAVROS2 与 onboard 控制程序
地面站 QGroundControl（QGC），用于设置真实飞控的 MAV_SYS_ID

多实例仿真中，PX4 用 -i 指定实例编号，这个编号会映射为 MAV 系统 ID；MAVROS 通过 fcu_url 指定与 PX4 通信的 UDP 端口或串口。端口必须与实例一一对应。

PX4_GZ_MODEL_POSE 指定模型在 Gazebo 中的初始位置 (x, y)。第二及后续实例加上 PX4_GZ_STANDALONE=1，避免与第一个实例的 Gazebo 插件冲突。

多块飞控对应多台机载电脑，或同一台机载电脑的多个串口：

实测前，先用 QGC 逐块设置飞控的 MAV_SYS_ID：与启动命令中的 uav_id 一致，并且在集群内不重复。

注意事项与排查

多机时需要保证三件事：每个 PX4 实例的 -i 唯一（对应不同的 MAV_SYS_ID）；MAVROS 的 fcu_url 端口与对应 PX4 实例匹配；不同无人机使用不同的 ROS 命名空间。

问题 可能原因 排查建议
无法连接 MAVROS 端口号或串口不对 确认 fcu_url 与实际端口，检查 UDP 是否被防火墙拦截
多机互相干扰、心跳冲突 系统 ID 重复或端口占用 检查 -i、MAV_SYS_ID 以及 QGC 中的参数
话题混杂 没有使用命名空间 在 launch 文件中增加 namespace 参数
模型位置重叠 初始位姿相同 为各实例设置不同的 PX4_GZ_MODEL_POSE
