Mid-360S 使用教程

发表于2026-05-06|更新于2026-09-28|感知与机载硬件
|总字数:4.1k|阅读时长:20分钟

Livox Mid-360S 是一款常用于移动机器人、无人机、SLAM、建图和避障的 3D 激光雷达。它通过以太网输出数据，在 ROS 2 中通常配合 Livox-SDK2 和 livox_ros_driver2 使用。

本文记录 Ubuntu 22.04 + ROS 2 Humble 下从硬件连接、网络配置、驱动安装到点云查看的完整流程。

一、硬件与网络准备

1. 连接设备

Mid-360S 接 DC 9 ~ 27 V 电源，网口连接电脑或交换机。注意事项：

  • 电脑和雷达必须在同一个网段。
  • 多网卡电脑要确认使用的是连接雷达的有线网卡。
  • 初次调试建议关闭防火墙，避免 UDP 数据被拦截。

查看网卡名称：

常见网卡名有 enp108s0、eno1、eth0 等。注意：ip addr 输出中接口名后面的冒号只是显示格式，命令里一般不要带这个冒号。

2. 配置电脑 IP

电脑 IP 只需要满足两点：

  • 和雷达 IP 在同一网段。
  • 不与雷达或局域网中其他设备冲突。

例如雷达在 192.168.1.0/24 网段，可以把电脑网卡设置为 192.168.1.5：

其中 enp108s0 需要替换为自己的有线网卡名。

3. 确认雷达 IP

如果已经知道雷达 IP，直接跳到下一步。否则可以通过以下方式获取：

  1. 看设备标签、说明书或出厂配置文档。
  2. 用官方的 Livox 工具在同网段内发现设备。
  3. 使用 Mid-360 协议中的广播发现功能获取 lidar_ip 和 cmd_port。

字段 含义

五、接入算法时需要确认什么

Mid-360S 常用于 FAST-LIO、LIO-SAM、VINS、YOPO 等感知或定位模块。接入算法时重点检查三件事。

1. 话题名称

2. 坐标系

驱动默认的 frame 通常是 livox_frame。如果算法使用 base_link、body、camera_init 等坐标系，需要让 TF、算法配置和消息中的 frame_id 保持一致。

3. 外参位置

三类外参作用不同，不要混用：

外参 作用
MID360s_config.json 中的 extrinsic_parameter 改变驱动发布的点云坐标，不会发布 ROS TF
ROS TF（static_transform_publisher、robot_state_publisher） 描述 ROS 坐标系之间的关系，RViz 和部分算法按 TF 做坐标变换
SLAM / 控制算法中的 extrinsic_T、extrinsic_R 算法内部使用的雷达到机体或雷达到 IMU 的外参

六、常见问题

1. ping 不通雷达

  • 检查雷达电源和网线。
  • 确认电脑 IP 和雷达 IP 在同一网段。
  • 确认命令里使用的是正确网卡名。

必要时重新配置电脑网卡：

2. 编译时报找不到 Livox-SDK2

如果没有结果，重新安装 SDK：

3. 运行时报找不到动态库

报错信息为 error while loading shared libraries: liblivox_lidar_sdk_shared.so 时，把 /usr/local/lib 加入动态库路径：

4. RViz 打开后没有点云

  • 只看原始点云时，Fixed Frame 设为 livox_frame。
  • 通过 TF 看机体系点云时，Fixed Frame 设为 base_link。
  • 确认 /livox/lidar 存在，并且有发布频率。
  • 确认 host_ip 是电脑网卡 IP，lidar_configs[].ip 是雷达 IP。

5. 改了 json 外参后点云没有变化或还是歪

然后重新编译并加载环境：

如果通过 TF 查看点云，检查 TF 是否存在：

6. 点云很卡

打开对应 launch 文件，适当降低 publish_freq：

7. 多雷达时无法区分话题

启用 multi_topic = 1，让不同雷达发布到独立话题；每个雷达配置不同的 lidar_ip，必要时让每个雷达使用不同网段或不同网卡。
